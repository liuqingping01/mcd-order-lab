# 🍔 麦麦怎么买最划算 `mcd-order-lab`

> **输入你想吃的东西，告诉你买套餐还是单点更省**，顺带把能用的券和活动摆出来，确认后直接下单。
>
> 基于**麦当劳官方 MCP 实时数据** · 1024程序员节 · 麦当劳程序员创意开发大赛 参赛作品

---

## 解决什么问题

麦当劳 App 里单品、套餐、优惠券、活动铺满一屏，真正难的不是"选什么"，而是：

**我就想吃个巨无霸——到底单点划算，还是买个三件套划算？**

官方渠道不会回答这个问题。它只列商品，不替你算"多花的钱换回了什么"。
本项目把麦当劳 MCP 开放的菜单、套餐组成、算价、券、活动编排成一条链路，**直接给出结论**。

### 算法口径

```
加价        = 套餐官方价 − 单品官方价
多得        = 套餐组成里，除目标商品外的其他项
可估值部分  = 多得项里「能单独下单」的部分，用官方算价求和
净收益      = 可估值部分 − 加价        // > 0 即买套餐划算
```

套餐里有些组成项**根本无法单点**（实测「可乐中杯」「麦乐鸡4块」官方算价返回 `productList: []`），
这类项**不计入金额**，只标注「套餐专属 · 无法单点」。因此净收益是**保守下界**，实际只会更划算。

## 购物车：攒几样，看能不能凑成套餐省一笔

商品卡片右上角点「+」加入购物车，右上角 🛒 打开抽屉可增减数量。
点「看看怎么买更省」，系统会扫描门店全部套餐，回答：**这几样全买单品划算，还是换套餐划算？**

算法（见 `src/cart.js`）：

```
基线价    = 官方算价(购物车原样全买单品)
方案价    = 官方算价(套餐 ×1 + 套餐没覆盖到的商品)
差价      = 方案价 − 基线价        // 负数 = 更省
```

套餐里多出来的东西（含无法单点的套餐专属品）视为"白送"，不计入抵扣，
因此省下的钱是**保守下界**。

实测示例（杭州国大城市广场店）：

| 购物车 | 全单点 | 换成套餐 | 结果 |
|---|---:|---:|---|
| 巨无霸 + 薯条 | ¥41.0 | 巨无霸三件套 ¥37.5 | **省 ¥3.5**，还多一杯可乐 |
| 巨无霸 ×3 | ¥79.5 | 三件套 + 2 个单点 ¥90.5 | 不划算，判定"无更省方案" |

## 界面结构

```
┌ 我想吃… ─────── 🛒 ②  🎫 优惠券 ⑦  🎉 活动 ⑬ ┐
│  [ 输入想吃的东西          ] [算一下]           │
│  或者直接挑一类：汉堡46 炸鸡12 小食18 饮品24 …   │
└──────────────────────────────────────────────┘
         ↓
  一句话结论 → 方案对比卡（可切换）→ 选中方案细节 → 结算（含领券）→ 折叠信息
```

- **唯一主入口**：「我想吃…」可直接输入（支持模糊叫法），也可点下方大分类挑
- **右上角小图标**：优惠券 / 活动，带数量徽章，点击右侧抽屉展开
- **有优惠的单品单独标注**：商品卡左上角标「省 ¥X」，并划掉原价
- **活动默认只显示标题**，点击才展开完整内容与配图，不长篇占屏
- **结算区**：金额随选中的方案联动，可勾选「同时领取 N 张优惠券」

## 特性

- **一句话出结论**：填「巨无霸」→ 直接告诉你买三件套还是单点，多花多少、多得什么、净赚多少
- **方案对比可切换**：单点与每个套餐各一张卡并排，点哪个看哪个的细节，不把信息全堆在一屏
- **价格以官方为准**：全部取自 MCP `calculate-price`，不自造价格规则；菜单展示价与官方价冲突时**显式提示差额**，不静默给结论
- **扫描全量套餐**：门店全部 56 个套餐类商品逐一比对组成，不是只挑几个推荐位
- **排序懂人情**：不只看净收益——多人餐净收益绝对值往往最高，但偏离"我就想吃一个堡"。单人份、加价小的优先，净收益最高的作为「加价升级」备选另行展示
- **券与活动顺带带上**：官方 App 本来就有的能力，这里只是搬到决策现场，不作为卖点
- **热量只在最后附一行**：买麦当劳的人不会因为几十千卡改主意，所以营养**不参与决策**，仅作购物车附加展示
- **零依赖**：只用 Node 内置模块，`git clone` 后直接 `node src/server.js`，**不需要 `npm install`**
- **安全默认**：Token 只存在于服务端，浏览器永远拿不到；**默认不下单**，需显式二次确认
- **诚实降级**：任一步 MCP 失败都会在页面明确提示，不静默返回看似正常的结果

## 快速开始

### 1. 申请 MCP Token

访问 [https://open.mcd.cn/mcp](https://open.mcd.cn/mcp) → 右上角【登录】（手机号验证）→ 【控制台】→ 【激活】→ 同意协议 → 复制 Token。

### 2. 配置

```bash
git clone https://github.com/liuqingping01/mcd-order-lab.git
cd mcd-order-lab
cp .env.example .env
# 编辑 .env，填入 MCD_MCP_TOKEN=<你的 Token>
```

### 3. 运行

```bash
node src/server.js
# 打开 http://localhost:5173
```

要求：Node.js ≥ 18（用到内置 `fetch`）。

### 4. 在手机上用（可选）

页面已做移动端适配（触控目标、底部抽屉、安全区）。手机与电脑连**同一个 WiFi** 后：

```bash
HOST=0.0.0.0 node src/server.js
# 启动时会自动打印局域网地址，例如 http://192.168.x.x:5173，用手机浏览器打开即可
```

> ⚠️ `HOST=0.0.0.0` 会对**同一局域网内的所有人**开放本服务，请只在可信网络下使用；
> 默认（不设 HOST）只监听本机，Token 与订单数据不出电脑。
